# Amotorg v3.0 — генератор счёта и акта

Статический сайт на Eleventy (11ty) с **автозаполнением через DaData**. Счёт и акт создаются в браузере, PDF формируется из отдельного чистого печатного HTML. Никакой базы данных, регистрации или постоянного Node.js-сервера в production не требуется.

## Возможности

- Поиск исполнителя и заказчика по ИНН через DaData: название, КПП, адрес и (для исполнителя, при наличии) данные руководителя для подписи.
- Поиск банка по БИК: наименование и корреспондентский счёт. **Расчётный счёт организации автоматически получить нельзя** — его нужно указать вручную.
- Поиск автоматически запускается после паузы при вводе полного ИНН или БИК. При этом **вручную изменённые поля не перезаписываются**. Кнопка «Найти по ИНН / БИК» позволяет явно перезаполнить поля.
- Ручное редактирование абсолютно всех реквизитов, номера и даты счёта и акта, данных подписантов.
- Привязка к договору (название, номер, дата) и комментарий в счёте и акте.
- Услуги, количество, валюта, НДС, расчёт с точностью до копеек, сумма прописью.
- Кнопка **«Новый счёт»** сохраняет исполнителя, банковские реквизиты и подписанта, очищает заказчика/позиции и увеличивает цифровой номер счёта.
- Адаптивная форма, предпросмотр, экспорт/импорт JSON, автосохранение в localStorage (старые черновики v1/v2 совместимы).
- Печать и сохранение в PDF **только документа** (без сайта, шапки, меню и формы). Для сохранения выберите в диалоге браузера «Сохранить как PDF», A4 и выключите колонтитулы.

## Быстрый запуск локально

Нужно **Node.js 22+** и API-токен DaData. Имя `DADATA_TOKEN` рекомендуется; старое `dadata_token` также поддерживается для совместимости.

```bash
npm install
cp .env.example .env
# В .env замените DADATA_TOKEN на свой настоящий токен
npm run dev
```

Откройте адрес Eleventy, обычно `http://localhost:8080`.

**Даже в `npm run dev` маршрут `/api/lookup` работает** за счёт обработчика Eleventy. Для проверки: `http://localhost:8080/api/lookup?type=bank&query=044525225`. Если токен не настроен, получите JSON с кодом `TOKEN_MISSING` (это ожидаемое поведение).

> `.env` и `node_modules` исключены через `.gitignore`. Не размещайте токен в `src`, HTML, JavaScript браузера или JSON-экспорте. Без токена вся форма продолжает работать, но автозаполнение будет недоступно.

## Netlify — рекомендуемый хостинг

1. Загрузите исходники Amotorg в приватный или публичный репозиторий GitHub, **не включая `.env`**.
2. В Netlify импортируйте Git-репозиторий. Файл `netlify.toml` уже устанавливает `npm run build`, директорию `_site` и функции из `netlify/functions`.
3. В **Site configuration → Environment variables** создайте `DADATA_TOKEN` с настоящим ключом. Переменная должна быть доступна для Functions (обычно scope `All`).
4. Опубликуйте проект через Netlify Deploy. При изменении токена запустите новый Deploy.
5. Проверьте `/api/lookup?type=bank&query=044525225` на домене сайта и кнопку в форме.

`netlify dev` — дополнительный способ локального запуска с эмуляцией функций. Но `npm run dev` уже поддерживает API без Netlify CLI.

**Важно:** публикация одной папки `_site` через Netlify Drop **не публикует серверную функцию**, и автозаполнение работать не будет. Используйте Git deployment или Netlify CLI с исходниками.

## Cloudflare Pages (альтернатива)

- Подключите репозиторий к Pages, укажите Build command `npm run build`, Output directory `_site`, Node.js 22+.
- Добавьте секрет/переменную `DADATA_TOKEN` в настройки Pages (Preview/Production по необходимости).
- Маршрут `/api/lookup` реализован в `functions/api/lookup.js` и автоматически развернётся вместе с проектом при Git deployment.
- Нельзя опубликовать только `_site`: функция находится в исходниках.

## Техническая схема

`Браузер → GET /api/lookup?type=party&query=ИНН → серверная функция → DaData`

`Браузер → GET /api/lookup?type=bank&query=БИК → серверная функция → DaData`

DaData: `findById/party` и `findById/bank`. `DADATA_TOKEN` остаётся на сервере, в браузер передаётся только нормализованный результат. Данные формы не отправляются на сервер при создании счёта или акта. ИНН и БИК попадают в запросы API и могут присутствовать в логах хостинга.


## Перед реальным использованием

- Проверьте КПП, название, статус организации и полномочия подписанта. Руководитель из DaData не всегда является фактическим подписантом.
- Проверьте расчётный счёт: его нельзя найти только по ИНН или БИК.
- Уточните ставку НДС, основание оплаты и формулировки по вашему договору. Генератор не заменяет бухгалтерскую или юридическую проверку.
- Система не хранит документы централизованно. Если браузер очистит localStorage, черновики исчезнут — периодически сохраняйте JSON.
- Для публичного коммерческого сервиса с высоким трафиком настройте лимиты, защиту от злоупотреблений и мониторинг запросов DaData на стороне хостинга.

## Структура

```
src/index.njk                   форма, предпросмотр двух документов
src/assets/invoice.js          работа формы, автозаполнение и печать
src/assets/dadata-lookup.js    браузерный запрос к своему API
src/assets/calculations.js     суммы/НДС/сумма прописью
src/assets/styles.css          оформление редактора
src/assets/print.css           чистая печатная A4-версия
lib/dadata-service.mjs         единая безопасная логика DaData
netlify/functions/lookup.mjs   серверная функция Netlify
functions/api/lookup.js        серверная функция Cloudflare Pages
.eleventy.js                   сборка и локальный /api/lookup
```
